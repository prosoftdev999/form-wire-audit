# Event-phase capture

The final phase begins from the complete DOM, runtime state, and form-associated custom-element state visible at `q096`. It contains seventy-two interaction tasks, but neither `event_intents.ndjson` nor `event_listeners.ndjson` is in browser time: the capture aggregator grouped records by recorder source. Query ids are opaque and do not encode chronology. `event_clock_sync.ndjson` contains exact `(local_tick, coordinator_tick)` beacon pairs for every recorder. Each recorder clock is affine over this capture. Recover coordinator time from those beacons; interaction chronology and listener registration order are the ascending recovered times. There are no timestamp ties. The phase is stateful across interactions, so listener lifetime, synchronous callback mutations, and microtask effects from one interaction can change later rows.

`event_listeners.ndjson` is the listener registry at the start of the phase. `node_id`, `type`, `capture`, `once`, and `passive` have their DOM meanings. `initially_active` says whether the listener is registered at `q096`; relative registration order comes from the recovered coordinator times, not file position. Callback actions are captured as normalized operations. `set_attr`, `set_runtime`, `set_parent`, and `set_face` use the same patch shapes as the earlier mutation files. `add_listener` and `remove_listener` change the registry by `listener_id`. `dispatch` synchronously dispatches the named event at the named target. `queue_microtask` appends its action list to the current task's microtask queue. Action `when` predicates are evaluated from live state immediately before that action. `target_is` compares the event target id, `runtime_equals` compares one captured runtime field, `attr_equals` compares one live attribute, `listener_active` tests current registry membership, `all` is conjunction, and `not` negates its child predicate.

Use normal DOM dispatch ordering. The propagation path is snapshotted from the target's parent chain before any listener runs. Capture listeners run root-to-parent, then target capture listeners, then target non-capture listeners, then bubbling listeners parent-to-root. For each node/phase, use the active matching listeners in recovered registration order at the moment that node/phase begins. A listener added during that same node/phase does not join its current snapshot; a listener removed before its turn is skipped. A `once` listener is removed immediately before its callback runs. `stopPropagation()` stops travel to later nodes but does not suppress other listeners on the current target. `stopImmediatePropagation()` also stops the remaining listeners on that target. `preventDefault()` from a passive listener has no effect.

A nested `dispatch` action is synchronous and has no form-activation default of its own. Microtasks do not run between event listeners or before the outer click's activation step. After the outer click dispatch finishes, take the activation checkpoint, then drain queued microtasks FIFO; any state or listener changes made by those microtasks persist into the next interaction.

For each event intent, the click target is the candidate submitter for the recorded `form_id`. At the activation checkpoint, recompute ownership from the live tree. If the click was canceled, or the target is no longer an enabled submit/image control owned by that form, no validation or request occurs: `validation_performed` is false, `invalid_ids` is empty, `would_submit` is false, and `request` is null. `entry_manifest` is still the normalized would-be entry list for that form at the activation checkpoint; use the click target as submitter only when it is associated with the form at that moment. If activation does proceed, use the same validation and request rules as the earlier phases. Microtask changes happen after this row's manifest/request has been captured.
